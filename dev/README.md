# Разработка Childgram

Основа — [официальный Telegram для Android](https://github.com/DrKLO/Telegram),
12.10.6 (7112), коммит `f2908b14133bbffbf7ab04f641ecb5bfaf533242`.
Исходники и закреплённые upstream-подмодули находятся прямо в этом репозитории.
Основной код: `TMessagesProj/src/main/java/org/telegram`; интерфейс — `ui`,
логика клиента — `messenger`, нативная часть — `TMessagesProj/jni`.

## Поведение Childgram

Эти изменения включаются в обеих Childgram-сборках: dev (`-PchildgramDev`)
и release (`-Pchildgram`). Родительские ограничения не зависят от режима отладки.
Обычная upstream-конфигурация сохраняется.

**Доступ к чатам.** Каналы и группы открываются только при текущем членстве
аккаунта. Обычные пользователи открываются штатно; сообщения, пересланные из
незнакомых источников в разрешённый чат, остаются видимыми. Проверка применяется
при входе в чат, профиль, форум, историю или предпросмотр, а также перед
вступлением по ссылке и через общую папку. Создание собственных групп и каналов
разрешено. Вступление родителем с другого клиента может открыть доступ после
обновления сведений об аккаунте — список не замораживается при установке.

Для бота требуется подтверждённое сервером право писать пользователю
(`bots.canSendMessage`). Это также относится к inline-ботам, miniapps и активным
кнопкам ботов. Первичный START и выдача нового разрешения писать блокируются.
Положительный ответ кешируется на 60 с; офлайн можно пользоваться ранее
подтверждённым ботом. Неизвестное состояние не считается разрешением.
Если автора активной bot-кнопки нельзя определить по сообщению, действие
отклоняется. Пассивные ссылки, копирование текста и пересылки этим не блокируются.

Комментарии поста доступного канала открываются даже без членства в связанной
группе. Исключение относится только к подтверждённой ветке этого поста,
не ко всей группе. Оно не даёт права вступать в группу ради отправки комментария.

**Приглашения.** Пункт скрыт из интерфейса настроек. При выходе приложения
на передний план для авторизованных аккаунтов проверяется основное правило
приглашений; при необходимости оно меняется на «Никто». Исключения сохраняются
и проверяются после записи. Это настройка Telegram-аккаунта, поэтому результат
виден и в других клиентах. При ошибке сети проверка повторяется; неполный набор
исключений не отправляется.

**Время в чатах.** В настройках под конфиденциальностью добавлен пункт
«Время в чатах» с подписью «Сколько времени на что потрачено». Экран показывает
день в текущей временной зоне устройства, список чатов и служебных экранов,
общее время и почасовую диаграмму. Можно выбрать отдельную строку или общий итог
и переходить по дням от первой записи до сегодняшнего дня.

Учёт предназначен для времени видимого приложения: фон, блокировка экрана
и picture-in-picture не учитываются. Полноэкранное воспроизведение видео
выделяется внутри общего времени, без повторного прибавления к итогу.
Записи хранятся локально в закрытых данных приложения отдельно для каждого
Telegram-аккаунта; содержимое сообщений не записывается. Измерение длительности
использует монотонные часы, а UTC-интервалы пересчитываются в дни и часы выбранной
временной зоны. Промежуточное сохранение выполняется каждые 10 с;
при аварийном завершении возможна потеря последнего несохранённого интервала.
Когда база превышает 100 МБ, появляется ручная очистка с подтверждением,
сохраняющая текущий день и 7 предыдущих полных дней.

**Ссылки и язык.** Обычные сайты направляются во внешний браузер независимо
от настройки встроенного. Telegram-ссылки, включая прямые `t.me/s/...`, сначала
проходят проверку доступа в клиенте. Дальнейшие переходы внутри внешнего браузера
Childgram не контролирует. Новые строки интерфейса находятся в стандартных
ресурсах: английский по умолчанию и русский перевод.

## Релизы и обновления Childgram

Release проверяет `https://update.childgram.org/android.json` при открытии приложения,
не чаще одного раза в 6 часов; в настройках есть «Проверить обновления».
При сетевой ошибке автоматическая попытка повторяется через 15 минут.
Dev-пакет обновления release не предлагает. Штатный сервер обновлений Telegram
для Childgram не используется. В окне написано «Доступно обновление Childgram»;
суффикс `alpha` остаётся в номере версии, отдельной надписи «новая бета» нет.

Загрузка начинается по нажатию пользователя. Перед передачей APK системному
установщику проверяются размер, SHA-256, пакет, версия и совпадение подписи
с установленным приложением. Разрешение установки APK выдаёт пользователь
в Android. Прерванная загрузка начинается заново; после перезапуска приложения
скачанный файл повторно не используется.

`.github/workflows/release.yml` запускается вручную на основной ветке и создаёт
**черновик** релиза. Перед запуском увеличьте `CHILDGRAM_VERSION_CODE`, обновите
`CHILDGRAM_VERSION_NAME` в `gradle.properties` и `dev/release-notes.md`. Версия
определяет тег `v<version>` и имя APK `childgram-<version>-arm64.apk`.
Workflow собирает APK в Docker, проверяет закреплённый сертификат и добавляет
APK, `android.json`, `SHA256SUMS` и открытый отпечаток сертификата в черновик.
Повторное использование опубликованного номера или существующего тега запрещено.
Публикует проверенный черновик человек; workflow этого не делает.

GitHub environment `release` должен содержать секреты `TELEGRAM_API_ID`,
`TELEGRAM_API_HASH`, `CHILDGRAM_RELEASE_KEY_BASE64` (существующий `.p12`) и
`CHILDGRAM_RELEASE_KEY_PASSWORD`. Не создавайте новый выпускной ключ для CI.
Ограничьте environment основной веткой и включите ручное одобрение сборки.
Значения секретов не входят в исходники, логи или отдельные артефакты workflow;
API-реквизиты, как и прежде, присутствуют внутри APK.

После публикации `.github/workflows/update-feed.yml` выбирает опубликованный
Childgram-релиз с наибольшим version code, включая prerelease. Черновики исключены.
До первого выпуска отдаётся `{"schema_version":1,"available":false}`.
Неполный релиз, несовпадающий хеш или повторный code останавливают публикацию
ленты; прежняя версия Pages остаётся доступной. Удаление/снятие релиза тоже
обновляет ленту, но уже установленное приложение не понижается автоматически.

Проверки без публичного выпуска:

```sh
python3 -m unittest discover -s dev/tests -p 'test_release.py' -v
./dev/build --release
./dev/emulator --release install
./dev/check-release --device
./dev/emulator --release smoke
# Локальный образец артефактов, явно помеченный как непригодный для публикации:
python3 dev/release.py package --local --output .local/release-fixture
```

`check-release --device` проверяет обработку JSON, отмену/ограничение загрузки,
проверку установленного подписанного APK и его доступность через FileProvider.
APK с теми же package/version и посторонним тестовым ключом отклоняется.
Тестовый APK с чужой подписью никогда не устанавливается. Проверки не создают
релиз, не меняют версию приложения и не требуют авторизации аккаунта.

Pages включается отдельно в настройках репозитория: Source **GitHub Actions**,
custom domain **update.childgram.org**, **Enforce HTTPS** после выдачи сертификата.
В environment `github-pages` разрешите основную ветку и теги `v*`, поскольку
событие публикации релиза связано с тегом. Подробный план DNS и отдельного сайта
в [общей документации](https://github.com/Childgram/childgram.org/blob/main/doc/updates.md)
(локально `../doc/updates.md` относительно корня Android).

## Где находятся инструменты

- Сборка: Docker Desktop, Linux AMD64, официальный `Dockerfile` Telegram.
  Java 17, Gradle 8.13, SDK 36/35, Build Tools 36.0.0/35.0.0, NDK 27.2.12479018,
  CMake 3.22.1 находятся в образе `childgram-android:36-ndk27`.
  В upstream Dockerfile добавлен SDK 35 для закреплённого подмодуля Media3.
- Кэш Gradle: отдельный Docker volume `childgram-gradle`.
- Эмулятор: уже установленный на этом Mac SDK в `~/Library/Android/sdk`.
  ARM64 Android 14 / API 34 с Google APIs. Новые глобальные SDK не нужны.
- Изменяемые данные эмулятора, ключи и логи: `.local/` внутри проекта.
  Сборочные результаты Gradle остаются в каталогах `build/` и `.cxx/` модулей.

Linux-инструменты SDK/NDK требуют AMD64; на Apple Silicon Docker выполняет их
через эмуляцию архитектуры. Первая сборка скачивает несколько гигабайт и заметно
дольше повторных. Docker ограничен 8 CPU и 14 GiB памяти; Gradle использует
до 4 workers, нативная компиляция — до 4 процессов.

Android Emulator работает непосредственно на macOS с Hypervisor.Framework:
[ускоренный эмулятор внутри Docker не поддерживается](https://developer.android.com/studio/run/emulator-acceleration).
Android Studio для командной сборки не требуется.

## Ключи

1. Войти в [my.telegram.org/apps](https://my.telegram.org/apps) и открыть
   **API development tools**. Создать своё Android-приложение.
2. Заполнить `.local/telegram.properties`:

   ```properties
   TELEGRAM_API_ID=ваш_числовой_api_id
   TELEGRAM_API_HASH=ваш_api_hash
   ```

   Это реквизиты Telegram API, не токен бота. Шаблон:
   `dev/telegram.properties.example`. Файл исключён из Git и доступен только
   владельцу на этом Mac. Не отправляйте значения в чат или в коммит.
3. Выполнить `./dev/build`.

Без собственных реквизитов обычная сборка прекращается с инструкцией.
Для проверки запуска допускается явная команда `./dev/build --smoke`:
при пустых полях она использует опубликованные тестовые реквизиты Telegram.
Если собственные ключи уже заполнены, используются они.
Такой APK предназначен только для локальных проверок.
[Правила Telegram](https://core.telegram.org/api/obtaining_api_id).

Debug-ключ подписи создаётся автоматически в `.local/debug.keystore`,
отдельно от демонстрационного ключа upstream. Сохраняйте его, чтобы устанавливать
новые сборки поверх старых без удаления данных. Это не ключ для публикации.
API-реквизиты входят в APK; исключение из Git не делает их секретными внутри APK.

## Сборка, запуск, повторная проверка

Все команды ниже выполняются из корня Android-репозитория (`Childgram/android/`),
Docker Desktop должен быть запущен. Общие документы находятся уровнем выше,
в `Childgram/doc/`; Android-репозиторий можно клонировать и использовать отдельно.

```sh
# Один раз или после изменения официального Dockerfile:
./dev/build --image

# В первом терминале; окно эмулятора остаётся открытым до Ctrl+C:
./dev/emulator start

# Во втором терминале:
./dev/build
./dev/emulator install
./dev/emulator smoke
```

До заполнения ключей заменить `./dev/build` на `./dev/build --smoke`.
Для проверки без окна: `./dev/emulator start --headless`.
Остановить проектный эмулятор из другого терминала: `./dev/emulator stop`.

APK: `TMessagesProj_App/build/outputs/apk/afat/debug/app.apk`.
Пакет: `org.childgram.messenger.beta`. Название: **Childgram Dev**.
Сборка содержит только ARM64; она также подходит для ARM64 Android-устройств.
Эмулятор использует порт 5580; команды проверяют его имя перед обращением.
Данные обычного Telegram и других устройств этими командами не затрагиваются.
В форме входа флажок **Test Backend** переключает на тестовые серверы Telegram;
для обычного аккаунта оставьте его выключенным.

После изменения исходников повторить сборку, установку и `smoke`.
Инкрементальная сборка переиспользует кэш. `install -r` сохраняет данные приложения.
`smoke` выполняет холодный запуск, проверяет процесс и активный экран,
сохраняет снимок и проверяет буфер падений внутри проектного эмулятора.

## Проверки изменений

Сначала собрать актуальные исходники: проверки используют классы этой сборки.
Java и инструменты упаковки тестового APK запускаются в том же Docker-образе.

```sh
./dev/build

# Локальные проверки без обращения к Telegram:
./dev/check

# Проверки внутри установленного приложения и чтение настройки приглашений:
./dev/emulator install
./dev/emulator smoke
./dev/check --device

# Только хранилище на Android, без чтения серверной приватности:
./dev/check --usage-device
```

`./dev/check` проверяет границы суток, смену временной зоны, переходы
на летнее/зимнее время, пересечение интервалов и календарную границу очистки.
Проверка правил приватности проверяет сохранение исключений и отказ
от неполной записи. Команда также собирает тестовый APK; без `--device`
его установка не выполняется.

`--device` устанавливает отдельный пакет `org.childgram.tests` с той же
локальной debug-подписью и запускает его против
`org.childgram.messenger.beta` в проектном эмуляторе. В Childgram должен быть
авторизован тестовый аккаунт. Проверяются обычный пользователь, неизвестный бот,
членство и неполные данные канала, аргументы открытия экрана и границы исключения
для комментариев. Синтетические пользователи и чаты добавляются только в память:
тест не создаёт диалоги, не сохраняет их в базу, не отправляет сообщения,
не вступает в группы и не запускает ботов.

Затем тест делает read-only запрос `getPrivacy` и требует основное правило
«Никто». Он сообщает только результат и количество исключений, без имён,
идентификаторов и ключей. Сам тест не вызывает `setPrivacy`; настройку при
обычном запуске обеспечивает приложение. Эти проверки не заменяют сценарии
реальных переходов, работы плеера и восстановления сети.
Результаты упаковки тестов находятся в `.local/checks/childgram/`.

Оба режима для устройства также проверяют настоящее SQLite-хранилище:
обновление интервала, суточные и часовые суммы, видео, очистку и VACUUM.
Используется фиксированный отрицательный тестовый идентификатор владельца;
только созданная тестовая база и её служебные файлы удаляются после проверки.
Пользовательская история не меняется. `--device` проверяет маршрутизацию браузера
с перехватом запуска Intent, не открывая сторонние приложения.
Инструментальные проверки перезапускают процесс клиента; после них открыть
приложение заново или выполнить `./dev/emulator smoke`.

## Логотип Childgram

Общий мастер-логотип хранится в рабочей директории уровнем выше Android:
`../branding/childgram-logo.svg`. Экспорт из него: `python3 ../branding/export.py`
(Python 3 и `rsvg-convert`). Квадратный PNG без внешних полей остаётся рядом с SVG.

Готовые Android XML-ресурсы находятся в `dev/res/` и входят только в Childgram
dev/release через существующий overlay. Android-репозиторий собирается независимо
от наличия общего `branding/` и инструментов экспорта. Обычная upstream-сборка
сохраняет оформление Telegram.

Лаунчер использует адаптивный зелёный значок с белым самолётиком и следом C;
есть обычный вектор для Android до 8 и монохромный слой для тематических иконок.
Все старые launcher aliases показывают тот же логотип, включая обновление
приложения с ранее выбранной альтернативной иконкой. Выбор иконок Telegram
скрыт в настройках Childgram. Системная заставка Android 12+ также использует
новый знак; вступительная карусель приложения остаётся upstream.

## Отладка

```sh
./dev/emulator logcat
./dev/emulator debug
```

Первая команда показывает системный лог только процесса Childgram.
Вторая открывает JDWP для уже запущенного приложения на `localhost:8700`.
Подключить **Remote JVM Debug** в IDE к этому адресу; для точных точек останова
использовать исходники той же сборки. Можно также подключать Android Studio
через **Attach Debugger to Android Process** к `org.childgram.messenger.beta`.
После сеанса или перед повторным подключением после перезапуска приложения:
`./dev/emulator adb forward --remove tcp:8700`. Команда `debug` намеренно
не перезаписывает уже занятый forwarding.

На этом Mac установлена Android Studio 2023.1. Для полноценного Gradle Sync
upstream требует более новую Studio (README Telegram указывает 2025.1.4).
Docker-сборка, эмулятор, logcat и JDWP не зависят от обновления IDE.
Не запускайте автоматическую установку host SDK ради Docker-сборки.
Отладка Java/Kotlin подготовлена; интерактивная C++/LLDB-отладка отдельно не настроена.

Логи сборки: `.local/logs/`; эмулятора: `.local/android/emulator.log`.
Для нестандартного SDK задать `CHILDGRAM_ANDROID_SDK`.
Скрипт создания AVD умеет использовать установленный здесь старый avdmanager
с имеющейся Java 8, не меняя системную Java. Для современных command-line tools
используется `JAVA_HOME`; для старых можно задать `CHILDGRAM_AVDMANAGER_JAVA_HOME`.

## Подписанный кандидат для установки напрямую

Проверено 3 октября 2026 года после переноса в `Childgram/android/`: `afatRelease`
собран в Docker, подпись и параметры готового APK проверены, установка
`org.childgram` поверх существующего пакета в проектном AVD прошла успешно.
Все 114 инструментальных проверок release, включая SQLite-хранилище, прошли.
Холодный запуск подтверждён (`TotalTime: 447 мс`), снимок экрана просмотрен,
падений приложения в проверенном буфере нет. На приветственном экране ещё
сохраняется оформление Telegram; это не готовое оформление публичного выпуска.

Выпускной идентификатор Android — **`org.childgram`**, название — **Childgram**.
Dev-пакет `org.childgram.messenger.beta` сохранён, чтобы не потерять существующую
авторизацию и статистику. Два приложения устанавливаются рядом; выпускной пакет
требует отдельного входа. Последующие обновления `org.childgram` устанавливаются
поверх него с тем же ключом, без удаления данных.

Версия Childgram задаётся отдельно от Telegram в `gradle.properties`:
`CHILDGRAM_VERSION_NAME` и `CHILDGRAM_VERSION_CODE`. При каждом опубликованном
обновлении увеличивать код версии; номер Telegram остаётся в `APP_VERSION_NAME`.
Первый кандидат — `0.1.0-alpha.1`, код `1`, ARM64.

```sh
./dev/build --release
./dev/emulator --release install
./dev/check-release --device
./dev/emulator --release smoke
```

APK: `TMessagesProj_App/build/outputs/apk/afat/release/app.apk`.
Это `afatRelease`: отладка выключена, код и ресурсы оптимизируются стандартной
конфигурацией Telegram, ограничения Childgram включены. Сборка требует собственных
Telegram API-реквизитов и существующего выпускного ключа. Smoke-реквизиты,
dev-подпись и произвольные дополнительные Gradle-аргументы здесь не допускаются.

Ключ уже создан локально в **`.local/signing/`**:

- `childgram-release.p12` — закрытый ключ, PKCS#12, RSA 4096, alias `childgram`;
- `password.txt` — случайный пароль; не выводить в терминал и не присылать в чат;
- `certificate.pem` и `certificate.sha256` — открытый сертификат и его отпечаток.

**До распространения сохранить всю папку `.local/signing/` в защищённой резервной
копии вне этого компьютера.** Хранилище ключа и пароль необходимы вместе.
Каталог имеет права `700`, файлы — `600`; каталог исключён из Git. Резервную копию
можно держать в зашифрованном хранилище или менеджере паролей с вложениями.
При потере восстановить эту папку из копии. Создание нового ключа не восстановит
возможность обновлять ранее установленные APK.

Открытый отпечаток закреплён в `dev/release-certificate.sha256`; его можно публиковать.
`dev/signing-key --create` нужен только для первоначального создания ключа нового
проекта и отказывается перезаписывать ключ или заменять уже закреплённый сертификат.
Сборка не генерирует выпускной ключ автоматически. Все инструменты подписи работают
в существующем Docker-образе; пароль передаётся из файла и не попадает в аргументы
процесса или логи.

После сборки автоматически выполняется `./dev/check-release`: проверяются подпись
и закреплённый сертификат, идентификатор и название APK, отсутствие отладки, ARM64,
независимые provider authorities/account type и включение Childgram в release.
Отчёт и SHA-256 APK сохраняются в `.local/checks/release/`.
`--device` дополнительно проверяет установленный оптимизированный APK: реальные
флаги режима, доступ к синтетическим чатам и SQLite-хранилище. Авторизация не нужна;
тестовые чаты находятся только в памяти, история проверяется в отдельной тестовой
базе. Тестовый APK из `.local/checks/release/` не распространять: он предназначен
только для локальной инструментальной проверки. Эта проверка не заменяет
запуск APK и ручные сценарии. Воспроизводимость APK независимой сборкой пока
не подтверждена; подпись подтверждает издателя, а не безопасность кода.

## Границы текущих сборок

Dev предназначен для разработки; подписанный alpha-кандидат — для ручной проверки.
В обеих сборках отключены FCM/Firebase SMS, покупки, passkeys и автоматическое обновление
официального Telegram. Используется штатный режим без Google push.
Google Maps не имеют настроенного ключа; экраны карт отдельно не проверены.
Проверки запуска, настроек и ограничений доступа не подтверждают доставку
сообщений, звонки и фоновые уведомления.
Перед публичным выпуском остаются проверка входящих сообщений и фоновой доставки,
Firebase/Maps по потребности, оформление вступительных экранов и канал обновлений.
Иконка и системная заставка используют логотип Childgram; часть вступительных
экранов пока унаследована от Telegram. Исходные лицензии
сохраняются. GitHub-форк [Childgram/cg-android](https://github.com/Childgram/cg-android)
подключён как `origin`; изменения Childgram и APK ещё не опубликованы.

## Обновление исходников и очистка

Перед обновлением сохранить свои изменения. Обновления upstream следует сливать
осознанно; после них выполнить:

```sh
git submodule update --init --recursive --depth=1
./dev/build --image
./dev/build
```

Для очистки сборочных результатов можно передать Gradle задачу `clean`:
`./dev/build --smoke clean`.
Не удаляйте `.local/` целиком без резервной копии ключей: там находятся также
данные Android и авторизация приложения. Docker-образ и volume принадлежат
только Childgram; не используйте глобальный `docker system prune` для очистки проекта.
